# TASK.md — Duskwing

Аркада в духе flappy-механики: одна кнопка, пять уровней с целями, бесконечный режим после прохождения.
Проект портфельный — качество кода и архитектуры важнее скорости.

Этот файл читается один раз в начале фазы. Постоянные правила поведения — в `CLAUDE.md`.

## 1. Стек

- Vite + React + TypeScript (strict). Менеджер пакетов — **npm**. Bun не использовать.
- PixiJS `^8.20.1` — единственная рантайм-зависимость помимо `react` / `react-dom`.
- `@pixi/react` **не ставить**. Pixi монтируется императивно в `useEffect`, React вне кадрового цикла.
- Vitest — только на чистую логику. Без jsdom, без тестов рендера.
- Без Tailwind, без UI-китов, без state-менеджеров. CSS — один файл плюс модули по необходимости.
- Деплой: GitHub Pages. В `vite.config.ts` прописать `base: '/duskwing/'`.

### Главное архитектурное правило

`src/game/**` — чистый TypeScript. **Ни одного импорта `react` и ни одного импорта `pixi.js`.**
Логика знает только о числах и своём состоянии. Рендер получает состояние снаружи.

```ts
// src/game/types.ts
export interface Renderer {
  init(canvas: HTMLCanvasElement, theme: Theme): Promise<void>;
  setTheme(theme: Theme, crossfadeMs: number): void;
  draw(state: GameState, dtMs: number): void;
  resize(width: number, height: number): void;
  destroy(): void;
}
```

Pixi — реализация этого интерфейса в `src/render/pixi/`. React — оболочка в `src/ui/`.
Нарушение этой границы — повод откатить изменение, а не «поправить потом».

### Структура

```
src/
  game/                 # чистая логика, покрыта тестами
    constants.ts        # физика и размеры мира
    types.ts            # GameState, LevelConfig, Theme, Renderer
    levels.ts           # конфиги 5 уровней (данные, не код)
    themes.ts           # визуальные темы уровней (данные)
    physics.ts          # интеграция, коллизии
    Game.ts             # конечный автомат + шаг симуляции
    progress.ts         # localStorage: рекорды, разблокировки
  render/
    pixi/
      PixiRenderer.ts   # реализация Renderer
      textures.ts       # процедурная генерация текстур
      layers/           # Sky, Celestial, Ridges, Weather, Ground, Foreground, Grade
      entities/         # Pipes, Bird
  ui/                   # React: Menu, LevelSelect, Hud, LevelClear, GameOver
  hooks/useGameLoop.ts
  App.tsx
```

## 2. Мир и физика

Логическая сетка **360 × 640**, земля 92 px. Всё в логических единицах, масштаб — забота рендера
(`resolution: devicePixelRatio`, `autoDensity: true`).

Шаг симуляции — фиксированный, 1/120 с, с аккумулятором; рендер интерполирует. Кадровую `delta`
из Pixi не использовать, брать `ticker.deltaMS` и клампить накопление 250 мс (вкладка в фоне).

Базовые константы (значения уровня 1 — в его конфиге, эти общие):

| Параметр | Значение |
|---|---|
| радиус птицы (визуальный) | 13 |
| радиус хитбокса | 10.5 |
| максимальная скорость падения | 780 px/s |
| ширина трубы | 64 |
| позиция птицы по X | 104 |

Коллизии: круг против двух прямоугольников. Потолок не убивает — скорость обнуляется, птица упирается.
Земля убивает.

## 3. Уровни

Уровень пройден, когда набрана цель. После пятого открывается бесконечный режим.
Все параметры — данные в `levels.ts`, новый уровень должен добавляться одним объектом без правок кода.

```ts
export interface LevelConfig {
  id: number;
  name: string;
  target: number;           // сколько труб пройти
  gravity: number;
  flapVelocity: number;     // отрицательное
  pipeSpeed: number;
  pipeGap: number;
  pipeSpacing: number;
  gapDrift: number;         // предел разброса: и от центра лётной зоны, и между соседними просветами, px
  runwayMs: number;         // пауза до первой трубы
  warmup: PipeShape[];      // виды первых препятствий: 'both' | 'top' | 'bottom'
  ramp: { speedPerPipe: number; gapPerPipe: number; minGap: number } | null;
  mechanics: {
    movingPipes?: { amplitude: number; periodMs: number };
    airflow?: { zones: number; strength: number };  // вертикальный снос
  };
  themeId: ThemeId | null;  // null — темы как данных нет: считается по счёту
}
```

| # | Название | Новое | Цель |
|---|---|---|---|
| 1 | Сумерки | ничего, обучение | 10 |
| 2 | Ночь | быстрее, просвет уже | 15 |
| 3 | Гроза | трубы ходят по вертикали | 20 |
| 4 | Каньон | зоны восходящих/нисходящих потоков | 25 |
| 5 | Пустота | всё сразу, минимальный просвет | 30 |

### Уровень 1 — точные значения

Новичок не должен раздражаться. Это не «чуть проще», это заметно проще:

```ts
{
  id: 1, name: 'Сумерки', target: 10,
  gravity: 1450, flapVelocity: -430,
  pipeSpeed: 120, pipeGap: 210, pipeSpacing: 260,
  gapDrift: 60, runwayMs: 2500,
  ramp: null,                 // скорость и просвет внутри уровня не растут
  warmup: ['bottom', 'bottom', 'bottom', 'bottom', 'top', 'top', 'top'],
  mechanics: {}, themeId: 'dusk'
}
```

**Кривая видов препятствий.** Скорость и просвет на уровне 1 не растут — это по-прежнему так.
Но вид препятствия — другая ось, и по ней рост нужен: новичок не должен встречать полноценный
просвет первым же экраном.

| Препятствия | Вид | Чему учит |
|---|---|---|
| 1–4 | только нижнее, потолка нет | перелетается с запасом, промахнуться почти невозможно |
| 5–7 | только верхнее, пролетается снизу | летать вниз тоже надо |
| 8 и дальше | обычный просвет 210 | собственно игра |

Порядок именно такой потому, что **первые препятствия без потолка безнаказанны для частых
взмахов** — а именно ими новичок и отвечает на панику. На полном просвете та же реакция убивает.

Одностороннее препятствие ставится в край своей полосы: свободный проход при этом максимальный.
При обычной постановке центра худший разброс оставлял бы на падение 34.5 px вместо 154.5 —
то есть требовал бы взмаха чаще, чем раз в 0.22 с, что обучением не назовёшь.

**Последнее препятствие перед сменой вида идёт новому виду навстречу.** Без этого первое
препятствие нового вида упирается в ограничение разброса и оказывается строже последующих:
первый в жизни потолок давал 94.5 px запаса против 154.5 у следующих — кривая обучения шла
вспять. Нижних поэтому четыре, а не три: последнее из них уступает место верхним.

Тесное место при этом переезжает на препятствие старого вида, и это выгодный размен: на нижнем
опасность — падение, лекарство — взмах, а лишние взмахи без потолка безнаказанны. На верхнем
всё наоборот: паническая реакция новичка и есть ошибка.

Задаётся полем `warmup` в `LevelConfig`, то есть данными: ветки по номеру уровня в `Game` нет,
и та же возможность есть у всех уровней и у бесконечного режима.

Плюс обязательное:

- **Мгновенный рестарт** — меньше 300 мс от смерти до управляемой попытки, без подтверждений и
  промежуточных экранов. Это главный фактор: пауза между попытками раздражает сильнее сложности.
- На первых трёх попытках уровня 1 показывать подсказку по управлению, дальше не показывать.
- Просветы не прыгают: соседние отличаются не больше чем на `gapDrift`.

### Бесконечный режим

Тот же движок, конфиг с плавным `ramp`. Тема интерполируется по счёту: палитра и грейд перетекают
от `dusk` к `void`, погода переключается на порогах. Отдельного кода уровней это требовать не должно.

## 4. Фон — девять слоёв

Цель: фон живой и заметно разный на каждом уровне, но **никогда не мешает читать трубы**.

Все текстуры генерируются процедурно один раз при старте через `renderer.generateTexture()`.
Бинарных ассетов в репозитории нет.

| # | Слой | Параллакс | Реализация |
|---|---|---|---|
| 0 | Небо | 0 | `Sprite` с текстурой градиента: нарисовать в offscreen canvas 2D (4 стопа), отдать в `Texture.from(canvas)` |
| 1 | Светило и звёзды | 0.03 | `Container` + спрайты; ореол — спрайт с `blendMode: 'add'`; `cacheAsTexture(true)` |
| 2 | Дальний гребень | 0.12 | `TilingSprite` из `RenderTexture` силуэта, построенного `Graphics` по сид-функции |
| 3 | Ближний гребень | 0.28 | `TilingSprite`, темнее и крупнее |
| 4 | Дымка | 0.20 | `TilingSprite`, `blendMode: 'screen'`, альфа ≤ 0.2 |
| 5 | Погода | 0.6–1.2 | `ParticleContainer` (дождь, снег, светляки, пыль) |
| — | Игровой слой | 1.0 | трубы и птица. **Фильтров на нём нет никогда** |
| 6 | Земля | 1.0 | `TilingSprite` |
| 7 | Передний план | 1.5 | `TilingSprite`, размытие силой 2–3 **запечено в текстуру** (`ctx.filter` при генерации), рантайм-`BlurFilter` не вешается: силуэты статичны, а бюджет в два активных фильтра занят грейдом фона и ближних слоёв. Живёт строго в полосе `FOREGROUND_BAND_HEIGHT` px над линией земли |
| 8 | Грейд | — | спрайт-виньетка `blendMode: 'multiply'` + `ColorMatrixFilter` на контейнере фона |

Прокрутка — `tilePosition.x -= speed * dtSec * parallax`. Никаких пулов объектов и ручного
переиспользования спрайтов фона.

### Тема уровня

```ts
export interface Theme {
  id: string;
  sky: [string, string, string, string];         // стопы градиента сверху вниз
  celestial: { kind: 'sun' | 'moon' | 'none'; x: number; y: number; glow: string; stars: number };
  ridgeFar: { color: string; amplitude: number; roughness: number; seed: number };
  ridgeNear: { color: string; amplitude: number; roughness: number; seed: number };
  haze: { color: string; alpha: number } | null;
  weather: { kind: 'none' | 'rain' | 'snow' | 'fireflies' | 'dust'; count: number; speed: number };
  ground: { base: string; top: string };
  foreground: { kind: 'none' | 'grass' | 'streaks' | 'rocks'; blur: number };
  grade: { saturation: number; brightness: number; tint: string; vignette: number };
  accent: string;                                 // цвет труб — задаётся темой
}
```

Палитры (ориентир, точные значения подобрать при реализации, но направление менять нельзя):

1. **dusk** — индиго `#151B3D` → `#3D4C8F` → `#8E6FA0`, низкое солнце, кремовый свет, тёплый грейд, погоды нет, переднего плана нет. Самый спокойный и читаемый уровень.
2. **night** — `#080C24` → `#1B2450` → `#3A2E5E`, луна и звёзды, светляки (40 частиц), холодный грейд, насыщенность −15%, передний план — травяные силуэты в блюре.
3. **storm** — `#1A2230` → `#2E3B48` → `#4A5560`, светила нет, дождь 300 частиц, вспышки молний, насыщенность −35%, передний план — струи в блюре.
4. **canyon** — `#2A1C2E` → `#7A3B46` → `#E08A54`, пылинки, **полосы ветра рисуют зоны потоков из механики уровня** — фон здесь работает телеграфом геймплея, полосы обязаны совпадать с реальными зонами `airflow`.
5. **void** — почти монохром `#05060E` → `#0E1024` → `#1A1233`, холодное свечение поверх монохрома — это слой дымки (`TilingSprite`, `blendMode: 'screen'`, бирюзовый оттенок), отдельного слоя сияния нет, тяжёлая виньетка, единственный цветной элемент в кадре — трубы цветом `accent`.

### Смена уровня

Кроссфейд, не подмена. Новая сцена строится невидимой, затем 700 мс: альфа старой 1→0, новой 0→1.
Значения `ColorMatrixFilter` при этом не интерполируются: у каждой сцены свой фильтр со своей темой,
и перетекание даёт сама альфа. Размен сознательный — на время перехода это 4 прохода фильтра вместо
двух, зато нет второй формулы грейда, которая обязана совпадать с первой. Старая сцена уничтожается
`destroy({ children: true, texture: false })` — общие текстуры остаются живыми.
Переход играется на экране «уровень пройден», геймплей в этот момент не идёт.

### Контракт читаемости (не нарушать)

- Игровой слой всегда выше слоёв 0–5 и никогда не получает фильтров.
- Яркость любого элемента фона в вертикальной полосе, где живут трубы, — не выше 45% яркости трубы.
  Яркость трубы берётся **измеренной на экране**, то есть после грейда и виньетки, а не из цвета
  `accent` в теме: виньетка опускает трубу заметно ниже её собственного цвета, и порог, считанный
  от темы, оказывается завышенным. Иначе каждую новую тему приходится пересчитывать руками.
- Замер — `scripts/readability.py` по скриншоту. Труба в нём опознаётся геометрически, по яркости,
  а не по константе темы: грейд и виньетка сдвигают её цвет, и сравнение с темой записывает часть
  трубы в фон. Решение принимается по 95-му перцентилю яркости фона, максимум — справочно.
- **Плотным может быть только то, что участвует в коллизии.** Прямоугольник столкновения —
  всегда `PIPE_WIDTH` в ширину и цвета `accent`. Всё, что выходит за него — вылет навершия,
  мягкий контур, декор снаружи — обязано читаться мягким: полупрозрачным, размытым, рваным
  по краю.

  Причина посчитана, а не выбрана. Перебор положений трубы и высот птицы настоящей функцией
  коллизии показывает: за прямоугольник птица достаёт **живой на любую глубину** — проверены
  все 200 px, дальше смысла нет. Верхняя граница `capOverhang` задаётся поэтому не
  досягаемостью, а геометрией: мягкие поля соседних препятствий не должны сливаться, то есть
  `capOverhang + edgeSoftness < (минимальный pipeSpacing − PIPE_WIDTH) / 2 = 88 px`. Это
  закреплено тестом `tests/themes.test.ts`.

  Плотная деталь снаружи прямоугольника означала бы смерть о то, что выглядит проходимым, —
  худший вид нечестности, какой может быть в этой игре.
- Альфа частиц погоды ≤ 0.35, режим смешивания аддитивный.
- Ни один слой фона не двигается с параллаксом в диапазоне 0.85–1.15, кроме земли и полос ветра:
  скорость, близкая к игровой, читается как ложное движение препятствия. Погода в таблице выше
  заявлена диапазоном 0.6–1.2 — пересечение с запретной полосой разрешается в пользу этого правила.
- **Полосы ветра — исключение с причиной.** Они не фон, а телеграф механики: показывают, где `airflow`
  сносит птицу вверх, а где вниз. Зоны неподвижны в мировых координатах, поэтому полосы идут ровно
  со скоростью мира; любое другое значение означало бы вторую формулу координат зон, а разъехавшись
  с физикой, полосы начнут врать игроку. Читаемость для них обеспечивается мягкими градиентами и
  низкой альфой. Список исключений в `src/render/parallax.ts` закрытый: новая строка там — ослабление
  этого контракта и требует такого же записанного обоснования.
- Передний план не поднимается выше `FOREGROUND_BAND_HEIGHT` (`src/game/constants.ts`) над линией
  земли, а просвет в эту полосу не опускается — проверяется `tests/foreground-band.test.ts`.
- Вспышка молнии: ≤ 120 мс, ≤ 0.25 альфы, и никогда в пределах 400 мс от появления новой трубы в кадре.
- `prefers-reduced-motion`: частицы выключаются, вспышек нет, кроссфейд мгновенный.

### Бюджет производительности

Цель — 60 fps на среднем мобильном. Одновременно активных фильтров не больше двух, частиц не больше 400,
`TilingSprite` не больше шести.

**Бюджет действует в геймплее.** На замороженном экране перехода превышение допускается: там живут две
сцены сразу, то есть 4 прохода фильтра вместо двух, до 12 `TilingSprite` и до 420 частиц. Бюджет писался
под то, что идёт под управлением игрока, а переход играется на экране «уровень пройден», где мир
заморожен и кадр никому не должен.

**Замер — внешней инструментовкой Playwright, дев-оверлея в игре нет.** Счётчик fps и draw-call живёт в
скрипте замера: он патчит `drawElements`/`drawArrays` у контекста страницы и читает фазу игры из атрибута
`data-screen`. Так лучше по двум причинам. Инструмент не попадает в прод-бандл вовсе — его не нужно
прятать за флагом и не нужно доверять тому, что дев-ветка вырезалась. И он не искажает то, что меряет:
оверлей с обновляемыми цифрами сам по себе стоит кадров и draw-call, то есть счётчик считал бы в том
числе себя.

## 5. Порядок работы

Каждая фаза заканчивается рабочим состоянием и коммитом. Следующая не начинается без одобрения.

**Фаза 0 — каркас.** Vite + React + TS strict, vitest, eslint, структура папок, пустая реализация
`Renderer`, `npm run dev` открывается. Никакой игровой логики.

**Фаза 1 — ядро без графики.** `constants`, `types`, `physics`, `Game`, `levels` (пока только уровень 1).
Тесты: падение под гравитацией, импульс, коллизия с трубой, коллизия с землёй, упор в потолок,
засчитывание очка ровно один раз, детерминизм при фиксированном шаге. Ничего не рендерится — проверка только тестами.

**Фаза 2 — минимальный рендер на Pixi.** Небо, земля, трубы, птица, тикер, DPR, ресайз.
Уровень 1 проходим от начала до цели. Фон пока плоский.

**Фаза 3 — система фона.** Все девять слоёв, генерация текстур, тема `dusk`. Контракт читаемости проверить глазами.

**Фаза 4 — оболочка на React.** Меню, выбор уровня, HUD, экраны «уровень пройден» и «игра окончена»,
прогресс в localStorage через try/catch. Счёт уходит в React только при изменении, не каждый кадр.

**Фаза 5 — уровни 2–5.** Механики движущихся труб и потоков воздуха, остальные четыре темы, кроссфейд,
бесконечный режим.

**Фаза 6 — доводка.** Звук на WebAudio (осцилляторы, без файлов), мьют, `prefers-reduced-motion`,
проход по производительности, деплой на Pages, README со скриншотами и описанием архитектуры.

## 6. Готовность

Проект считается готовым, когда:

- `npm run typecheck`, `npm run lint`, `npm run test` проходят без предупреждений;
- в `src/game/**` нет импортов `react` и `pixi.js` — проверяется тестом, который грепает исходники;
- уровень 1 проходится новичком с первых попыток, рестарт мгновенный;
- пять уровней визуально различимы на скриншотах без подписей;
- 60 fps на среднем мобильном, фон не мешает читать трубы ни на одном уровне;
- README объясняет архитектурную границу и почему она проведена — это главное, что читают в портфолио.

**Правило замеров.** Синтетический ввод (`dispatchEvent` на элемент) допустим как способ привести игру
в нужное состояние, но не как предмет замера: он минует попадание по слоям, и путь, который меряется,
оказывается недоступен живому игроку. Всё, где предмет замера — сам ввод, меряется кликом по координате.
